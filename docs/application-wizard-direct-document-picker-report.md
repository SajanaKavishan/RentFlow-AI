# Application wizard: direct document picker

Validated on 2026-10-05 on `feature/full-app-polish`. No branch changes, commits, pushes, or PRs were made. No backend, dependency, or platform permission configuration changed.

1. **Old navigation.** A wizard document row pushed ApplicationDocumentsScreen with an initial document type. The tenant then used the full workspace's type selector, Choose file, and Upload document before returning to the wizard.

2. **New flow.** A missing document row directly opens native Files selection. Its row supplies the existing DocumentType, so there is no repeated type selection or intermediate management screen. A valid selection automatically uploads to the same application and leaves the tenant on Documents information. Continue remains a separate action.

3. **Existing picker infrastructure.** Reuses the installed `file_picker` 12.0.0 single-file API with its existing `pdf`, `jpg`, `jpeg`, `png` filter. Selection, size/MIME mapping, and SelectedDocumentFile were extracted into a shared helper used by the wizard and standalone workspace. The previous screen import still exports SelectedDocumentFile for compatibility. No custom browser or new picker package was introduced. Provider files are read through the package's PlatformFile interface, preserving content-URI access rather than treating Android URIs as filesystem paths.

4. **Android permissions.** No broad storage permission is required or added. The installed Android picker implementation's custom-file branch uses ACTION_OPEN_DOCUMENT with CATEGORY_OPENABLE and MIME filters. Android target SDK remains 36. The built APK was checked: no READ_EXTERNAL_STORAGE, WRITE_EXTERNAL_STORAGE, or MANAGE_EXTERNAL_STORAGE permission is declared. Permission manifests are unchanged. The wizard never requests storage permissions or retries a denied permission automatically.

5. **iOS permissions.** Custom Files selection uses the installed Darwin implementation's UIDocumentPickerViewController for opening supported content types. No new Info.plist permission or Photos request was needed. Existing Camera/PhotoLibrary descriptions for other features remain intact. No Open settings action was added, because ordinary Files selection does not depend on an app-wide storage/Photos permission.

6. **Actual backend rules.** ApplicationDocumentService permits positive, readable files of at most **5 × 1024 × 1024 bytes**, inclusive. Allowed MIME headers are **application/pdf**, **image/jpeg**, and **image/png**, compared without case sensitivity. DocumentType must be the existing enum: Identity Document 0, Income Proof 1, Employment Letter 2, Other 3. The backend chooses stored extensions from MIME and sanitizes the original filename; it does not separately require a filename extension or perform magic-byte validation. The existing mobile extension filter and mapping are preserved, without adding a new server rule. Local validation rejects empty/oversized contents and unsupported selections before an API call; provider-reported oversize is rejected before reading bytes into memory.

7. **Upload behavior.** Uses the existing authenticated multipart POST `/api/rental-applications/{applicationId}/documents`, with the existing application ID, selected row's enum value, filename, MIME, and bytes. The application is refetched before upload; identity and Draft/ChangesRequested state are checked while backend ownership/lifecycle validation remains authoritative. Choosing/Uploading state is immediate, and duplicate row taps and wizard navigation are blocked while active. Returned metadata must match the application/type before it is applied. Successful metadata is merged by document ID, then the authoritative list is refetched. An earlier missing-document validation message clears once required documents are confirmed.

8. **Cancel/failure.** Cancellation returns to the same step without API calls, data changes, or an error. The native picker's own resume is distinguished from an ordinary app resume, so cancel does not accidentally initiate a refresh. Access/read errors display a safe choose-another-file message, with no raw provider/path details. Upload failure remains on Documents, shows a row error, and retains a valid selected file in memory for explicit retry. No local success is fabricated. An empty/malformed success acknowledgment or mismatched application/type is rejected. If a confirmed upload's list refresh fails, its returned metadata remains visible with Reload documents; progression waits for list recovery.

9. **Existing document restoration.** Entry loads the server document list for the same application. An idle app resume schedules a fresh application/document fetch after the next UI frame. Native picker returns and in-flight operations do not trigger conflicting refreshes. Prior filenames/types are restored from server records. Identity Document and Income Proof remain the only required types; Employment Letter is recommended and Other optional. Existing required-document gates and submission refetch remain intact.

10. **Uploaded rows.** Display actual API filenames and Uploaded state, with readable titles, olive status/file icons, white cards, and subtle borders on the cream page. Tapping opens a compact action sheet with View document entries for the real records and Add another file when editable. The backend allows multiple documents of the same type, so additions preserve old records. No destructive replacement semantics were invented. Viewing uses the existing authenticated download endpoint, obtains its temporary signed URL, and opens it externally. The signed URL is not persisted. Read-only lifecycle states do not offer another upload.

11. **Standalone workspace.** ApplicationDocumentsScreen remains present. Profile → Application documents → TenantDocumentsScreen → ApplicationDocumentsScreen was exercised in a regression test. It retains its full document-type selector, manual choose/upload, existing viewing/download, and lifecycle-restricted deletion behavior. Its only changes are reuse of the shared picker/model, shared constants/MIME mapping, and safe picker error handling.
